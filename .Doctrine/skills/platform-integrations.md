# Skill: Platform Integrations ("Spaces")

> Load when work integrates with an external enterprise platform — Hugging
> Face, Snowflake, ServiceNow, Salesforce, Jira, Zendesk, SAP, Workday, and
> the like. These are systems you build *on* and *with*, not infrastructure you
> provision (that's `skills/cloud-*`) and not the MCP transport layer (that's
> `skills/mcp-tooling.md`, though a platform may also expose an MCP server).
> Coordinates with `roles/interop-engineer.md`.

## The stance: integrate, don't reinvent — and govern the boundary
Every one of these platforms is a **third party that holds or acts on your
data**. Crossing that boundary engages the same law as any external action:
data leaving the building, a new dependency, credentials, and often a paid
contract. Treat each integration as a governed interface, not a convenience.

## Before the first call — the intake checklist
- **Auth model.** OAuth2 / API key / JWT / SSO? Where does the credential live?
  (Secret manager — never the repo, non-negotiable #2.) What is the *minimum*
  scope needed?
- **Data direction & sensitivity.** What flows out, what comes in, is any of it
  PII/regulated? Data leaving to a third party is a §5 + a compliance question
  (`skills/privacy-compliance.md`).
- **SDK vs raw API.** Prefer the vendor's supported SDK; it must pass
  `standards/dependency-policy.md`. Pin the version.
- **Rate limits, quotas, cost.** Know them before load; a paid tier is §5.
- **Failure semantics.** Timeouts, retries with backoff, idempotency keys for
  writes (`skills/resilience.md`). Never assume the platform is up.

## Governance rules for every platform boundary
- **Writes to a system of record are escalated the first time (§5):** creating
  a Salesforce opportunity, a Jira issue, a ServiceNow ticket, or pushing a
  Hugging Face model/dataset **acts on the outside world**.
- **Secrets in the manager, scoped, rotated.** One integration's leak must not
  become every integration's breach.
- **Sandbox/dev instance first.** Salesforce sandboxes, Jira test projects, a
  Snowflake dev schema, HF private repos — validate there before prod.
- **Log the call, not the payload.** Redact tokens and personal data from
  integration logs.

## Platform catalog — starting patterns (extensible; not the whole world)
| Platform | Kind | Integrate via | First-call watch-items |
|----------|------|---------------|------------------------|
| **Hugging Face** | ML models/datasets/Spaces | `huggingface_hub` SDK, Hub API, MCP | private-repo default; token scope; license + model card of what you pull; Spaces = paid compute |
| **Snowflake** | Cloud data warehouse | connector / SQLAlchemy, key-pair auth | warehouse compute = per-second cost; role-based access; never `ACCOUNTADMIN` from an app |
| **Salesforce** | CRM (system of record) | REST/Bulk API, OAuth | sandbox first; governor limits; writes to prod records = §5 |
| **ServiceNow** | ITSM / workflow | Table API / Scripted REST, OAuth | instance scoping; ticket creation acts outward; PII in incident bodies |
| **Jira** | Issue tracking | REST v3, OAuth/API token | test project first; webhook loops; bulk rate limits |
| **Others** (Zendesk, SAP, Workday, GitHub, Notion, Slack) | varies | vendor SDK / REST / MCP | same intake checklist — auth, data direction, cost, failure, sandbox |

Add a row when a new platform enters scope; the **intake checklist and
governance rules above are the contract** — the table is only a head start.

## Review checklist add-ons
- [ ] Credential in the secret manager, minimum scope, rotation path
- [ ] Data direction + sensitivity assessed; PII/regulated flows compliance-reviewed
- [ ] SDK passes dependency-policy and is version-pinned
- [ ] Writes to a system of record gated on human sign-off (§5) the first time
- [ ] Timeouts/retries/idempotency for every outbound write
- [ ] Validated against a sandbox/dev instance before prod
- [ ] Rate limits/quotas/cost known; paid tiers escalated
