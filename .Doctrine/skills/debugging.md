# Skill: Debugging

**Scope.** Finding and fixing the *cause* of a defect — not the symptom — with
the least guesswork, and a regression test that proves it stays fixed. Load when
a test fails, a bug is reported, or behavior surprises you. Distinct from
`skills/observability.md` (production diagnostics), `skills/incident-response.md`
(production incidents), and `skills/loop-engineering.md` (the agent's own retry
discipline): this is dev-time bug hunting.

## Principles
- **Reproduce first, always.** A bug you cannot reproduce, you cannot fix — only
  guess at. Get a deterministic, minimal reproduction before touching code.
- **Read the actual error.** The full stack trace, the exact message, the failing
  assertion — read them completely before theorizing. Most bugs name themselves.
- **Cause, not symptom.** The place a failure surfaces is rarely where it
  originates. Trace back to the earliest point the state went wrong.
- **One change at a time.** Change one variable, observe, revert if it didn't
  help. Shotgun edits turn one bug into three and destroy the signal.
- **The bug is (probably) yours.** Suspect your own recent change before the
  compiler, the OS, or the library. `git diff`/`git log` the suspect window first.

## The loop (hypothesis-driven)
1. **Reproduce** — deterministic, minimal, fast. Strip everything not needed to
   trigger it; a shrinking reproduction often reveals the cause outright.
2. **Observe** — gather real evidence: the value, the state, the order of events.
   A logged fact beats an imagined one; print/log/breakpoint the *actual* state.
3. **Hypothesize** — one falsifiable guess ("X is null because Y ran before Z").
4. **Test the hypothesis** — the cheapest experiment that would prove it *wrong*,
   not right. Trying to refute your guess finds the truth faster than confirming it.
5. **Fix the cause**, then **prove it** with a regression test that fails before
   the fix and passes after (non-negotiable #3).

## Techniques (vendor-neutral)
- **Binary search the space.** Bisect the input (halve the data until it stops
  failing) and bisect history (`git bisect` to the exact commit that introduced it).
- **Minimal reproduction.** Reduce to the smallest program/input that still fails;
  often the act of shrinking *is* the diagnosis.
- **Rubber-duck it.** Explain the failing path aloud, line by line; the wrong
  assumption usually surfaces the moment you have to say it.
- **Trace to the origin.** Walk *backwards* from the crash to the first frame
  where an invariant broke — the fix belongs there, not at the crash site.
- **Differential debugging.** What changed between working and broken? — a commit,
  an input, an env var, a dependency version. Diff it.
- **Instrument, don't guess.** Add a temporary log/assert at the suspected
  boundary; confirm the state before hypothesizing further. Remove it before merge.

## Do
- Write the failing test *first* when fixing a reported bug — it reproduces the
  bug and becomes the regression guard in one move.
- Bisect when it worked at tag X and fails at HEAD (`git bisect` finds the commit).
- Fix the whole bug **class** when the cause is shared — audit for siblings before
  closing (a fix that leaves a twin defect is half a fix).
- Leave a log line or assertion that would catch this in one grep next time.

## Don't
- Don't "fix" by mutating code until the symptom disappears — that hides the cause
  and usually relocates the bug.
- Don't weaken, skip, or delete the failing test to go green (non-negotiable #4).
  The red test is the truth; the code is the suspect.
- Don't leave debug prints, `dbg!`, commented-out code, or a disabled test in the
  merged diff.
- Don't claim "fixed" without re-running the *original* failing reproduction and
  showing it now passes (anti-fabrication, §1).

## Review checklist
- [ ] A deterministic reproduction existed before the fix
- [ ] The fix addresses the root cause, not the surfacing symptom
- [ ] A regression test fails before the fix and passes after
- [ ] The whole bug class was swept (no sibling defect left behind)
- [ ] Debug instrumentation removed; a durable diagnostic left where it helps

## Common failure modes
Symptom-patching that relocates the bug; "cannot reproduce" closed as won't-fix
when the repro was merely non-deterministic; the fix with no test, so it silently
regresses; trusting a hypothesis you only tried to confirm; the shotgun edit that
green-lights the suite by accident while the cause lives on.
