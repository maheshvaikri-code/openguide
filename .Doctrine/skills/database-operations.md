# Skill: Database Operations

> Load with `roles/database-administrator.md`. This is *operating* the running
> database. For schema/query design read `skills/database.md`; for whole-system
> reliability read `skills/resilience.md` + `skills/incident-response.md`.

## Backups exist to be restored
- A backup you have never restored is a hope, not a backup. Schedule restore
  drills; record the timestamp of the last successful one.
- Know your **RPO** (how much data you can lose) and **RTO** (how long recovery
  may take) as agreed numbers — not vibes.
- Point-in-time recovery (WAL/binlog/oplog archiving) for anything whose loss
  hurts. Test the PITR path, not just the full restore.

## Migrations against a live database
- Review every migration for **lock scope** before it runs: which rows/tables,
  for how long, under production load.
- Prefer online/expand-contract: add nullable, backfill in batches, build the
  index `CONCURRENTLY`/online, swap, drop later. Never a blocking rewrite at peak.
- Have the rollback ready and rehearsed before you start. A migration with no
  reverse path is escalated (§5).

## Performance operations
- Read the plan before blaming the query — `EXPLAIN (ANALYZE)` / execution
  plans over guesswork.
- Index for the real access patterns; drop the unused (they tax every write).
- Watch bloat/fragmentation; schedule vacuum/analyze/OPTIMIZE/compaction on a
  cadence, not in a panic.
- Bound connections with a pooler; an exhausted connection pool is a
  self-inflicted outage.

## High availability & DR
- Replication topology chosen for the RPO/RTO, with failover *tested*, not
  assumed. A replica you have never promoted is untested.
- Monitor replication lag with an alert threshold; lag is silent data risk.

## Access & security
- Least privilege: application accounts get exactly their grants; no app runs
  as superuser. Keep migration/DDL credentials separate from runtime.
- Rotate credentials; store them in the secret manager, never in the repo
  (non-negotiable #2). Encryption at rest and in transit on by default.
- Audit logging for privileged and destructive operations.

## The destructive-operation rule
`DROP`, `TRUNCATE`, restore-over-live, replica rebuild, disabling backups — all
are irreversible or data-bearing and are escalated to the human (§5) before
execution. No exceptions to buy speed.

## Review checklist add-ons
- [ ] Last successful *restore* (not just backup) is recent and recorded
- [ ] RPO/RTO stated as numbers and met by the topology
- [ ] Every migration reviewed for lock scope; online path used on hot tables
- [ ] Rollback rehearsed before any prod migration
- [ ] Failover/PITR actually tested, not assumed
- [ ] Least-privilege grants; no secrets in repo; encryption on
- [ ] Destructive operations gated on human sign-off
